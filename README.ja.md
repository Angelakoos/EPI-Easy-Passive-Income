# EPI - Easy Passive Income

ようこそ！ここでは、インターネット接続を共有することでパッシブ（受動的）収益を得るためのアプリケーションやサービスをご紹介します。これらのプラットフォームは、私自身が**実際にテスト**し、**24時間365日**使っているものなので**推奨**できます。

> **注意**: 正確な収益を把握するために、**各プラットフォームを最低1か月**試用してみることをおすすめします。日によって収益が変動しやすいからです。  
> **家庭用（住宅）IPアドレス**は通常より高い収益をもたらしますが、**データセンターIP**もまた有利で拡張が容易、安価なVPSを利用することでコストを抑えられます。  
> このセットアップは**完全自動化・放置で収益**を得ることを目指しているため、適宜各プラットフォームのダッシュボードで収益を確認するだけでOKです。

## マルチプラットフォーム対応

ほとんどのプラットフォームは Windows、Mac、Linux、Android などに対応しています。しかしここでは **Linux** 向けの解説に重点を置いています。Linux はリソース消費が少なく、安価な VPS と組み合わせると非常にコスパが良いからです。接続するデバイスが増えるほど、収益可能性も高まります。

## インストール手順

ネット接続を共有して収益化を始めるための最もシンプルなステップをまとめました。

> **重要**: VPS を契約した際（例：IONOS など）、**コントロールパネル**で **ファイアウォール**の設定を**全ポート開放**（または必要ポートのみ）にしてください。サーバー上に機密データがない場合、全ポート開放での構築が簡単です。

### 1. システムの準備

以下のコマンドブロックをコピー＆ペーストで実行します。内容は：
1. **システムの更新 & 最適化**  
2. **基本パッケージ** (例：`nano`) のインストール
3. **Docker のインストール**  
4. **Watchtower のインストール**  
5. **月次のCronジョブ** (毎月1日4時) の設定
6. **不要ファイルの削除** などの処理

```bash
echo "[INFO] システムを更新＆最適化中..."
apt update && apt upgrade -y
apt install -y curl wget htop ufw git zip unzip nano

echo "[INFO] Docker をインストール..."
apt install -y apt-transport-https ca-certificates software-properties-common
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | apt-key add -
add-apt-repository -y "deb [arch=amd64] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable"
apt update && apt install -y docker-ce
systemctl start docker
systemctl enable docker

echo "[INFO] Watchtower（コンテナを自動アップデートするツール）をインストール..."
docker run -d \
  --name watchtower \
  --restart=always \
  -v /var/run/docker.sock:/var/run/docker.sock \
  containrrr/watchtower \
  --cleanup \
  --revive-stopped \
  --include-stopped \
  --include-restarting \
  --interval 3600 \
  --stop-timeout 30s

echo "[INFO] 毎月の Cron ジョブ(1日4時)を設定..."
(crontab -l ; echo "0 4 1 * * apt update && apt upgrade -y && apt install --only-upgrade -y docker-ce && apt update && apt install myst -y && (reboot || sleep 30 && reboot -f)") | sort - | uniq - | crontab -

echo "[INFO] 最後の掃除..."
apt autoremove -y && apt autoclean -y
```

> - **Watchtower** は1時間ごとにコンテナの更新をチェック。  
> - **Cron** は**毎月1日の4:00**(システム時間)に実行。  
> - VPS は更新後、自動的に再起動し常に最新状態を保つ。

#### 2.9 ByteLixir (Proxy)

[**ボーナス付き登録はこちら！**](https://bytelixir.com/r/NPONRRIEOSLD)

- **Dante** を SOCKS5 プロキシとして利用します。  
- ByteLixirのポータルで `socks5://USER:PASS@PUBLIC_IP:15000` を設定してください。

**ステップ A: `nano` でスクリプトを作成:**

```bash
nano /root/dante_bytelixir.sh
```

次の内容を貼り付けます:

```bash
#!/bin/bash
echo "[INFO] ByteLixir 用の Dante をインストール中..."
apt update && apt install -y dante-server

USER="YOUR_PROXY_USER"
PASSWORD="YOUR_PROXY_PASSWORD"
PORT="15000"
CONFIG_FILE="/etc/danted.conf"

INTERFACE=$(ip route | grep default | awk '{print $5}' | head -n 1)
if [ -z "$INTERFACE" ]; then
    echo "ネットワークインターフェースが検出できませんでした。$CONFIG_FILE 内で 'external' を手動設定してください。"
    exit 1
fi

cat > $CONFIG_FILE <<EOL
logoutput: syslog
user.privileged: root
user.unprivileged: nobody

internal: 0.0.0.0 port=$PORT
external: $INTERFACE

socksmethod: username

client pass {
    from: 0.0.0.0/0 to: 0.0.0.0/0
}

socks pass {
    from: 0.0.0.0/0 to: 0.0.0.0/0
}
EOL

useradd -r -s /bin/false \$USER
echo "\$USER:\$PASSWORD" | chpasswd

mkdir -p /etc/systemd/system/danted.service.d
cat <<EOC > /etc/systemd/system/danted.service.d/delay.conf
[Service]
ExecStartPre=/bin/sleep 10
Restart=always
RestartSec=10
EOC

systemctl daemon-reload
systemctl restart danted
systemctl status danted --no-pager
netstat -tuln | grep \$PORT

echo "[INFO] Dante がポート \$PORT で設定完了しました（ユーザー: '\$USER'、パスワード: '\$PASSWORD'）。"
```

**ステップ B: スクリプトに実行権限を付与し実行:**

```bash
chmod +x /root/dante_bytelixir.sh
bash /root/dante_bytelixir.sh
```
> `YOUR_PROXY_USER`, `YOUR_PROXY_PASSWORD` を独自の情報に置き換えてください。

### よくある質問 (FAQ)

1. **複数のプラットフォームを同時に導入できますか？**  
   はい！ ただしポートや環境変数が競合しないよう注意が必要です。

2. **コンテナを手動でアップデートするには？**  
   Watchtower があるので通常不要ですが、手動で行う場合は：
   ```bash
   docker pull イメージ名
   docker restart コンテナ名
   ```

3. **ログイン情報（クレデンシャル）を変える必要があるときは？**  
   - ほとんどのコンテナの場合：
     ```bash
     docker stop <container>
     docker rm <container>
     ```
     新しい環境変数を使ってコンテナを再作成すればOK。
